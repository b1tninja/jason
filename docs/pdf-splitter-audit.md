# The splitter specs against the splitter as built: an audit

Status: review (2026-10-11), read at commit `77623b4`. Nothing in the specs or the code was changed by this page. It compares what the splitter documents say with what `src/jason/tasks/split_*.py`, `library_browse.py`, `library_ocr.py`, `drive_pick.py`, `ui/src/views/Split*.tsx`, `PageGrid.tsx`, `Loupe.tsx`, `splitLoupe.ts`, `LibraryBrowser.tsx`, the limits registry, and `e2e/tests` do, and with what the user said while using it. General for any association: no name, street, vendor, or id here belongs to one; samples are made up.

The documents read: [pdf-splitter.md](pdf-splitter.md) (the design, 800 lines), [pdf-splitter-client-side.md](pdf-splitter-client-side.md) (research), [console/screens/split.md](console/screens/split.md) (the screen), [console/reconciliation-sixth-cut.md](console/reconciliation-sixth-cut.md) (the design agent's prototype against the build), [record-intake.md](record-intake.md) (the splitter's join), [instance-limits.md](instance-limits.md) (the registry), and [google-picker.md](google-picker.md) (a source the splitter docs never mention).

How a verdict is given: **code** means the code is right and the document must change; **doc** means the document states the intent and the code is the one that is short; **both** means neither is right and a decision is needed. Every row was checked against the file named; a row marked *unverified* was not.
