# Person steps: the inventory

Generated by `scripts/gen_person_steps.py` from the registered general definitions. Do not edit it: run the script and commit its output. `tests/test_person_steps_inventory.py` fails when this file differs from the script's output. The page that says what to do with it is [person-steps.md](person-steps.md).

A **person step** is a step a human does: kind `person` or `decision`. A wait that only a person's note ends, and a branch a person answers, are human edges of other kinds and are only counted (section 10 of the page).

## How to read a row

| Column | Says |
|---|---|
| Step | the step's id (`definition.N`); a step is never renumbered |
| Kind | `person` or `decision` (the board's, recorded by the secretary) |
| Roles | every office that may act, the primary first; `anyone` is any signed-in person |
| Cmd, Why | `Y` when the step has a command to copy, a why sentence; `-` when not |
| Clock | the date slot and its offset, and the basis (`law`, `documents`, `counterparty`, `provider`, `proposed policy`, `person`), with a cited section; `bd` after an offset is business days; `-` is no clock |
| Exit | `legal` (a law clock: no skip), `skip` (a skip rule), `na` (a not-applicable outcome); `-` is none |
| SOP | the procedure step it was built from; the letters after it say what that step carries: `c` a check, `l` lessons, `r` readings; `gone` is a drifted address |
| Cites | the sections its clock or why names (today only in prose, except a law clock's `cite`) |
| Missing | codes, from the list below, for guidance the step could already carry |
| Wanted | what the step is waiting to become (`check`, `job`, `plan`, `case`, `template`, `run`, `role`) |

Missing codes:

- `why`: no why sentence.
- `done`: no record named, so nothing says what done points to.
- `cmd`: a person step with no command (nothing to copy).
- `sop`: no procedure step it was built from (no lesson, check, or reading to show).
- `time`: no clock, so no date to remind from.
- `exit`: neither a skip rule nor a not-applicable outcome (a step that cannot be left must say how it is blocked).

A repeating step is marked `*` after its id (one clock and one nudge for each item). A date slot marked `*` in a definition's heading is set after the run starts.
