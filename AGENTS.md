# jason

HOA virtual agent. Orchestrates **payhoa**, **smud**, **idoxs**, Keeper (`keepersdk`), `jason.google`, and `jason.zoom`. PayHOA HTTP lives in the payhoa package; jason decides when to call it.

Workflows and skill-level “do not”s: **[SKILLS.md](SKILLS.md)**. Human setup: **[README.md](README.md)**.

## Design goals

Keep three layers apart. The specification is data. The implementation is reusable helpers. A task only applies a result.

- **Specification.** Mystique facts are the `Mystique` class in **[mystique](mystique/README.md)**: buildings, transaction rules, sync rules, known files, PayHOA folders, Drive roots, site pages, and governing documents. Add a fact as a class attribute there. Do not add a JSON spec, and do not hardcode the fact in a task, a default argument, or `config.py`. Use `KnownFile`, `PayhoaFolder`, and `SitePage`. A governing document is a `GoverningDocument` bound to a Drive id. An amendment is an `Amendment` mixin on `Document` and records the sections it changes. Do not add one `KnownFile` member per amendment. An association record is an `AssociationRecord` from Civil Code 5200, pinned on the Drive sync rule, library folder, or known file that holds it. A document the subdivider had to deliver is a `DeveloperDelivery`. `pin()` is the 5200 record. `deliver()` is the map, plan, common-area deed, public report, or plan set that is not one of those records. `developer_file()` groups the pins. An empty group is a missing document. A folder with no pin is unclassified. A document's `DocumentKind` says what it is, and `DocumentCategory` is the shelf; `documents.PROFILE` maps each kind to its shelf and its Civil Code 5200 record. `classify_document` applies the Mystique kind rules in order, by name, PayHOA folder, and library path. A name that matches none goes to the phrase rules in `jason.community.content`, then to a local model; a miss after all three stays a miss. The association's bank accounts and which is the reserve are `BankAccount` rows in `mystique/banking.py`. A letter template is a `DocumentTemplate` row in `mystique/templates.py`: a Drive Doc with `{VARIABLE}` tokens; a letter is a filled copy. The association's Google Groups are `GoogleGroup` rows in `mystique/groups.py` with a `GroupPurpose`; the Gmail sync keeps the groups each message came through and reads a group-rewritten sender from `X-Original-From` ([docs/gmail.md](docs/gmail.md)).
- **Private facts stay out of the specification.** People's names, emails, and phone numbers; which unit an owner rents; account numbers; settlement figures; and counsel's direct contact go in `data/spec/<name>.json`, which is never checked in. The specification merges them in through `jason.community.private.facts(name)`, and a missing file means none. Tests read made-up ones from `tests/fixtures/spec` (`conftest.py` sets `JASON_SPEC_DIR`), so they give the same results on any checkout. Facts the board keeps up to date belong in a register (docs/registers.md).
- **Implementation.** `jason.community.Community` is the abstract base. `load_mystique()` imports that class. Shared matchers (`assign_building`, `first_utility`) classify. They do not call PayHOA, Google, or Keeper.
- **Use.** Task code asks `Jason.community` and acts on the classification. A new decision is a new rule row, not a new function with a Mystique id inside it. Match order is part of the rule. A miss stays a miss.

Prefer classes, structured records, and enums over string tokens. JSON may store the word; the loader must turn it into a symbol before a task sees it. Closed sets already defined: `Building`, `Street`, `Parity`, `DocumentRule`, `Utility`. `BuildingRange` and `TransactionRule` are the records. Reach for those members (`Building.BLDG_2`, `Utility.SMUD`) instead of `"2"` or `"smud"`.

## Commands

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -U pip
pip install -e D:\code\payhoa
pip install -e D:\code\smud
pip install -e D:\code\i-doxs
pip install -e ".[dev]"
# Optional local catalog MCP (disk only):
pip install -e ".[mcp]"
# Optional SVG charts for the Markdown reports (matplotlib):
pip install -e ".[charts]"
# Optional model reader for scanned instruments (anthropic; needs ANTHROPIC_API_KEY):
pip install -e ".[models]"
# Optional QR codes for links in printed letters and notices (segno):
pip install -e ".[qr]"
```

```bash
pytest
jason login                    # interactive terminal only; once for Keeper
jason sync-bills --dry-run
jason-mcp                      # stdio; local catalog only
```

Copy `.env.example` → `.env` and fill Keeper record UIDs (never commit `.env`).

## Boundaries

- Amounts are **integer cents** (`6120` = $61.20).
- Non-interactive runs use `interactive=False` and **fail fast** (`KeeperAuthRequired`, `GoogleAuthRequired`). Do not open a browser unless a person passed `interactive=True`.
- Do not approve, deny, or assign requests. One exception, the board's of October 1, 2026: once `jason owner-info --apply --payhoa --yes` has recorded an owner's PayHOA owner-information answer in full (its tags written and nothing left for a person to enter), it marks that request complete with `OWNER_INFO_COMPLETED_COMMENT` (`mystique/forms.py`), emailed to the owner. An answer needing a person stays open. jason never deletes or edits an owner's submission.
- Do not submit delinquent accounts to a collection agency (sheet/CSV handoff only).
- Do not mail a letter on jason's own initiative. PayHOA's Mailroom (`jason mailroom`; USPS through Lob) prints, mails, and charges the association: `--pdf` with `--units` previews and lists the recipients; only `--send --yes` from a person mails it, and `--cancel ID --yes` cancels a letter still processing. Each sending is logged in `data/mailroom/sent.jsonl` with its letters and their communication ids. `--letters KIND`, `--events COMMUNICATION`, `--months YEAR`, and `--prices` only read. Billing is by printed page with PayHOA's address page counted (`payhoa.pricing`), and a sixth billed page adds $2.25 of postage a letter, so a PDF letter is four pages at most unless a person chooses otherwise.
- Never delete a live PayHOA form. Once a letter, QR code, or email links to a form, it is locked in `data/payhoa/forms.json` (`payhoa_forms.lock`): change it in place with `jason forms --payhoa KEY --update`, which keeps each question's id and answers. `--replace` refuses a locked form, and each owner-information send first checks that the form it links to is in PayHOA and on (`payhoa_forms.live_problem`).
- Do not invent CC&R quotes from file names; quote document body text only when you have the file.
- A request that runs a local model holds the GPU lock, and a store jason reads, changes, and writes back holds its store lock (`jason.locks`). A model job runs `jason.local_ai.preflight` first and fails fast on the CPU or short of commit. `jason local-ai` reports the stack; see [docs/document-tools.md](docs/document-tools.md).
- Drive text watermarks (e.g. diagonal DRAFT) **cannot** be removed via the Docs API; remove them in the Docs editor before export.
- Do not commit HARs, `.env`, or `secrets/google-token.json`.

## jason-mcp

`jason-mcp` serves the catalog already on disk (`data/payhoa.db`, `data/payhoa-files`) and the deed chain (`data/ownership.db`, deed extracts). It does **not** call PayHOA, Google, or Keeper. `recorder_search`, `recorder_detail`, and `recorder_priors` read the Sacramento public index. A hit is not a pin. `tax_account` reads the stored bills. `tax_search` queries the public tax index and does not download bill pages. `secured_parcel` and `secured_search` read the stored roll. `secured_roll` reads the bulk workbook for one parcel or for the community. `authorities` reads the statute pages `jason export-authorities` wrote from lawlibrary (the words of the law; `records.md` and `duties.md` are summaries); given a former Davis-Stirling section (Civil Code 1350-1378) it returns where the 2014 recodification put it, and given a current one it adds the section's changes since 2011, both from `jason law-history --export` ([docs/law-history.md](docs/law-history.md)): each successor row names its source (the Law Revision Commission's disposition table, its Comment, or a similarity candidate), and the statute text in force is the law. `index_coverage` reads the cached index against the processes and lists what is left to model. `unit_characteristics` reads the assessor's stored residential characteristics (living area, bedrooms, baths, year built) and the plan each unit matches. `solar_status` reads each unit's solar lease standing from the cached UCC filings; no filing is not proof of purchase. `mechanics_liens` lists every mechanic's lien lifecycle with its standing; an expired lien is unenforceable but still of record. `index_survey` counts the cache by family, process, and filing and lists the filings no class reads; a new filing there is a new rule row in `filings.py`, not a special case in a task. `permits` reads the City's permit collection as `jason permit-status --sync` saved it (`data/accela`): each open record's status, fees, conditions, and review marks; a fee line's date is the invoice date, and the collection's fees paid include the developer's building permits. `board_digest` is the entry point for what the board should know now. `jason-mcp --profile board` (or `JASON_MCP_PROFILE=board`) serves thirty-eight tools: the digest, the briefs, the budget, utility, vendor, pest, incident, insurance policy, reserve, reserve transfer, invoice, and reconciliation reviews, the mail, the Zoom meetings, the meeting records, and hearings, insurance, deadlines, open items, and party briefs, the lien and solar standings, the duties, and the law; AnythingLLM is registered with that profile. `unit_brief`, `escrow_brief`, `recent_filings`, `lifecycle_of`, `assessment_liens`, and `explain_filing` are the briefs: one unit on a page, what escrow can be told, what recorded since a date, where a document number sits, the association's own liens, and what a filing code is. Each carries its caveats; repeat them. A lien row's `namesakeRisk` means the filing dropped the deed's middle name; say so. `utility_brief`, `utility_accounts`, `utility_usage`, and `utility_payments` read the parsed SMUD and City bills (`data/utilities.db`) and the last payment audit: each account's meters and parcel as the bills state them, usage per day, abnormal usage (a reason to look, not a finding), next year's cost beside the budget line, and each PayHOA payment's bills, attachment, and split by budget line; jason changes nothing in PayHOA. `reserve_study` reads the reserve study PDFs on disk: the latest study's plan for a year beside the budget's transfer line and the reserve accounts, each study's Civil Code 5570 disclosure, and when the next site visit is due; the figures are the preparer's. `invoice_review` reads the last `jason invoices` review of every expense payment against its attachments (amount, vendor, date, reuse, category) with the per-vendor reader scorecard; it changes nothing in PayHOA. `ledger_validation` reads the last `jason ledger` check of the library's treasurer's reports against their source, PayHOA's "Treasurer's Report" packet: copies that are a run as generated (by SHA-256), copies filed under the wrong month, accounts a report printed that the ledger no longer carries for that date, and balances the ledger now reports differently; the printed report is the record of what the board was told. `books_report` and `ledger_query` read the books `jason books --sync` stored from PayHOA's general ledger (`data/payhoa/ledger.db`): profit and loss, categories by month, vendors, cash flow, balances, receivables without names, a check against PayHOA's budget against actual and its Profit vs Loss by Month, and entry queries that leave the units' own accounts out. `legal_cases` reads the association's legal matters from `mystique/cases.py` (forum, number, role, status, businesses involved with private persons by role only, counsel, insurer claims, events, money, each statutory duty's standing, and a settlement's released items priced from the claimant's cost of repair with the work on file for each); it is confidential, for directors and counsel, and a cost of repair marked for mediation (Evidence Code 1119) stays out of members' notices. `board_items` reads the board's running list of action items (each matter a review found that needs a board decision, with the board's own status, owner, meeting, and notes); an item is a matter to decide, never the decision. `cost_centers` sets the annexations' two assessment cost centers (the Phases 1 and 2 Property, A.C.A. 3 and 8; the Annexed Property) beside the DRE reports' cost center budgets, the monthly assessments charged in each, the budget's lines, and the reserve studies' funding plans; restoring them is the board's, with counsel. `developer_securities` reads the developer's DRE securities saved from Drive (data/developer-security) into a register by phase: agreements by type, bonds, and the releases that name them; a bond with no release on file may have been released without a copy reaching Drive, and OCR can misread amounts. `document_models` reads the stored document-model readings (`jason models`): per kind, how many library files a model read and completed, and each file's typed record and findings; a finding cites the statute when the law shapes the document, a confidential file's fields are held back unless asked, and a reading is evidence, not a pin. `document_references` reads the outlines and references `jason outlines` stored (`data/outlines`): each document's numbered sections, one section's text with what it cites and what cites it, every reference to a statute, section, or resolution number, and the findings (a cited section the outline lacks, a resolution number two Docs print, a statute cited by its pre-2014 number); references are read by a citation grammar, a finding is a lead for a person, and a scanned annexation's outline can miss subsections. `jobs_status` reads the job queue (`jason jobs`, run by `jason worker`; [docs/jobs.md](docs/jobs.md)): each job's command, resource, status, attempts, who confirmed a write, and the end of its log; it adds, runs, and cancels nothing. `reserve_transfers` sorts every movement on the reserve accounts from the stored ledger (regular, catch-up, and unscheduled contributions, borrowings, reimbursements, forwarded deposits, investments) and gives each borrowing its Civil Code 5515 record: the agenda's notice of intent to borrow, the minutes, the resolution, and the contributions that restored it within a year; a repayment is matched by amount, and whether the statute was met is the board's to say. `bank_reconciliations` reads PayHOA's bank reconciliations as `jason reconcile --fetch` stored them: months covered, each statement against the ledger (a difference the items in transit explain is marked), the items that never cleared with their age, transfers open on both sides, and why each open item may not have cleared (the same bank line held twice, a cleared twin, a voided bill payment, in transit); clearing or voiding an item is the treasurer's. `vendor_portal` reads a vendor's customer portal as `jason vendors --sync` saved it under `data/vendors/<key>` (ProActive Pest Control: each property on the master account, its plan, visits with the products applied and their EPA numbers, photos, documents, and invoices checked against their tickets) and, after `--verify`, each PayHOA payment to the vendor against the portal's payment and the attached invoice; jason signs in with the Keeper record named `<key>_record_uid`, only reads the portal, and never pays. `pest_program` reads the same record as a pest control program: each product by EPA registration number with its label, safety data sheet, and California rules once `jason pests --fetch` has run, the rodent stations' activity from the technicians' notes, visits by building, and the vendor's inspection reports ([docs/pest-management.md](docs/pest-management.md)); the declaration decides who pays, and jason directs no application. `insurance_policies` reads the last `jason policies` run: each policy (master package, umbrella, crime, D&O, the eight NFIP flood policies) term by term from its own declarations, beside the policy sheet and the specification, with its documents and findings (the sheet out of step, a renewed term not on file, a mailing address not the association's, the Civil Code 5800/5805/5806 limits, protective safeguards); the policies' own words are the AnythingLLM `insurance` catalog ([docs/insurance-policies.md](docs/insurance-policies.md)). `incident_history` reads the last `jason incidents` run: the association's maintenance history and insurance claims read from its repair paperwork (proposals, estimates, contracts, change orders, invoices, inspection reports, claim letters, and notices in PayHOA, email, the library, and the Drive folders `mystique/incidents.py` names), grouped into events and placed on units by street address and on buildings: each event's work (repair, maintenance, improvement, inspection; a maintenance vendor's calls are maintenance by rule), its standing against the master policy's $10,000 deductible (claimed, a claim candidate whose cost reaches it, under it, or cost unknown), causes, elements, vendors, estimated and paid amounts, and claim numbers ([docs/incidents.md](docs/incidents.md)); an event is a rule's reading, not a finding, whether a peril was covered is the insurer's answer, a claim's snippet is held back unless asked, and medical records are never read. `zoom_meetings` and `zoom_meeting` read the association's Zoom meetings as `jason zoom` synced them (`data/zoom`): each occurrence's kind by `mystique/zoom.py`'s topic rules (or a board meeting by the schedule's day), who joined, the transcript as speaker turns, the AI Companion summary and its next steps, and the schedule's meeting days with no meeting; the AI summary is not the minutes (no roll call, motion, or vote), and an executive session's or hearing's text is held back unless asked. `meeting_records` reads the last `jason meetings` catalog: every meeting's agendas, notices, minutes, transcripts, AI summaries, chats, attendance, and recordings across Zoom's cloud, jason's copy, Drive, the PayHOA library, and jason's drafts, placed by the dates their names carry (`mystique/meetings.py`), with each meeting's checks (minutes 30 days on, CIV 4950; a recording kept after the minutes against the Decorum Rules; a transcript that runs into executive session); it deletes nothing, and a kept recording may be under a litigation hold. With `date` it adds the files, folders, and photo albums the agenda links under each item; with `file` it gives every meeting and agenda item that linked a file (`jason meetings --links`), a lead for filing it, not a classification. A transcript that mentions an executive session or hearing is held back by `zoom_meeting` unless asked. `hearings` reads the disciplinary hearings `jason hearing` planned under Civil Code 5855 (notice 10 days before, the decision in writing within 14 days) and where each stands; jason creates a Zoom meeting only with `jason hearing --create --yes`, never keeps the host's start link, and never sends the notice or decides the discipline. `mail_checks` reads the same mail against jason's other records (old addresses, escrow clocks under Civil Code 4530, county tax bills and delinquency notices against the stored bills, bank statement balances, checks against deposits). `mail_brief` and `mail_item` read the association's paper mail as `jason mail` synced it from PostScanMail (`data/mail`): each item sorted by sender and words into legal notices, insurance cancellations and renewals, government notices, escrow requests, bank statements, bills, and checks, with the dates the letters tie to an action, and one letter's scanned text; jason only reads the mailbox and never asks PostScanMail to scan, forward, shred, or discard. `counterparties` lists who the association hears from and pays, by kind of source (government agency and its level, utility, insurer, bank, vendor, title company, law firm, manager), the other associations the mail names, and the letterheads no rule names; the directory is `mystique/senders.py`. `insurance_review` reads each policy on the sheet against the carriers' letters and the premiums PayHOA paid: the term in force, renewal notices and conditional renewals, premiums by term (a flood payment placed on the building whose renewal bill prints it), and claims; `association_calendar` lists the recurring deadlines (taxes, filings, inspections, insurance terms, the reserve study) with the PayHOA evidence each was done and past deadlines done late; a payment is evidence, not proof. `vendor_contacts` reads each PayHOA vendor's contact on file beside the people who write from its domains in the association's Gmail (headers only, from `jason gmail --sync`), with what a person should update, and PostScanMail's Gmail notices against the synced mail; jason reads no message body, sends no email, and changes nothing in PayHOA. `document_copies` reads the last `jason copies` run: every invoice and bill as one document with each copy the association holds (issuer's portal, email, PayHOA attachment, paper scan), the rule that joined it, the best copy by `mystique/copies.py`, and the PayHOA payment; every copy stays where it is. `record_locations` reads the last `jason drive` run: every Drive file placed by the specification's Drive roots and classified by the library's rules (kind, Civil Code 5200 records, confidential), every other place its content is held, the duplicates and versions in Drive, and the folders no path rule covers; jason moves, renames, and deletes nothing in Drive. `party_brief` puts one unit (by address) or one counterparty (by name, PayHOA vendor, or email domain) on a page across every store: a unit's owners by deed, PayHOA standing, requests, violations, threads with topics, letters, and the unit brief; a counterparty's payments by year, invoices and their payments, threads, letters, contacts, and Drive files saved from its email. `thread_topics` counts what the association hears about by topic (`mystique/topics.py`) and names the FAQ candidates; `new_owners` lists recent conveyances with the buyer's questions; `open_items` lists what is waiting on the association (threads awaiting us, pending requests, deadlines, insurance findings, unscanned mail, letters to act on, unpaid lien notices). `request_links` joins each PayHOA request to PayHOA's notices (by time) and to the owner's threads about its unit (by dates, topics, and subject words, with reasons), and drafts a request for each owner's emailed request PayHOA lacks (form from `mystique/requests.py`); it is read-only, and a draft is entered only by a person with `jason request-links --create THREAD --yes`. `email_intents` reads what each thread asks from its subject (complaint, maintenance, information or records, billing, question, the association's enforcement notice) and, for a complaint, question, or information request, where the answer is likely written: governing-document passages, library documents by kind, and PayHOA violations as precedents with their notice text (`mystique/topics.py`); `case_file` gathers one matter across the stores by its words; neither decides anything. `reply_needed` learns from the association's own replies which email it answers (reply rate and usual time by sender, by kind of party and intent, by kind of party) and lists the open threads that likely need a response, each with the history it was judged by. `budget_status` and `bank_accounts` read the finance snapshot `jason budget` took from PayHOA (budget against actual, year to date and full year, and the bank balances named from `mystique/banking.py`); the balances are Plaid's and can lag the bank. `library_search`, `library_status`, and `library_text` read the classified document library (`jason library`); each row keeps its method (name rule, phrase rule, local model), and a confidential file is held back unless asked for. `association_collections` reads the PayHOA ledger beside the association's own liens (release due, lien secures debt, owed with no lien, credit); it records nothing and sends nothing. `title_watch` reads every unit's liens as one standing each against the title (`attention=True` for what a person acts on); a presumption is not a release, and another association's lien is never on the unit. `read_document` and `document_readings` read the text of the recorded copies on disk into the concept records (stamp, citations with relation, annexed property); a reading is evidence, and a supersession it states is pinned in `mystique/annexations.py` only after a person reads it. `records_request` lists the recorded instruments the association's record lacks, with the order form's fields and the copy cost. `passage_search` ranks the extracts' passages for a question; `extraction_scorecard` scores a reader (regex, the local vision model through Ollama, or the hosted model) against the pinned facts; `read_scan` reads one image-only PDF with the local vision model; `anythingllm_status` reads AnythingLLM itself: its chat and embedding settings against jason's, each workspace's embedded documents and retrieval, and what is wrong with the command that fixes it; starting it, applying settings, and re-embedding are `jason anythingllm` commands with `--yes`. `anythingllm_query` asks AnythingLLM, by catalog (`authorities`, `association-records`, `mail`, `jason-pages`, or a legal case's own `case-<key>`) or the shared Mystique workspace, and labels each source with its catalog; a `jason-pages` source is a summary. Each legal case with a `drive_folder` in `mystique/cases.py` is its own catalog (`jason cases --fetch-files`, then `jason anythingllm --sync --catalog case-<key>`): confidential, never in the shared workspace, synced only when named, titled with its case number, never moved into or out of another catalog, and without the medical and veterinary records the case holds back unless a person passes `--include-held`. The local readers never leave the machine; the hosted one and AnythingLLM fail fast without their keys and send nothing. `manager_context` is a professional community manager's context pack for a task (`jason review`; [docs/manager-review.md](docs/manager-review.md)): the base prompt (the order of authority under Civil Code 4205, the method, the privacy rules), the task's prompt from `mystique/prompts.py`, and the sources numbered in order of authority; work from it, cite by id, and quote, and it decides nothing. `records_inventory` is the Civil Code 5200 inventory with its gaps, and `duty_brief` maps one manager duty to its statute, records, cadence, and the documents' passages; neither decides that a record exists or a duty is met. Amounts are integer cents. `expand_deed_anchors` grows the local deeds out from the pinned chain; a solved parcel drops out and `remaining` is the candidate pool.
